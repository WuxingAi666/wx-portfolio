围绕个人求职中的职位筛选、重复操作与消息回复，采用 Tampermonkey 浏览器脚本连接 DeepSeek，并以本地 FastAPI 服务记录操作事件、展示统计与运行反馈。

实际实现与职责

  • 浏览器交互

    集中维护多组候选选择器，处理职位包含 / 排除筛选、滚动翻页、焦点与输入事件；提供手动启停和运行日志。

  • 模型调用

    使用最近八条聊天消息作为上下文调用 DeepSeek 生成回复；招呼语使用用户预设内容，配置通过 GM 存储保留。

  • 本地监控

    FastAPI 接收事件，SQLAlchemy / SQLite 保存记录与每日计数，SSE 向看板推送更新，并提供本地简历图片接口。

处理链路

以下为处理流程示意。

设计取舍与实践复盘

方案怎样演变

最初尝试程序启动浏览器并由本人登录，但出现空白页、未完成该方案；最终改为在已登录浏览器内运行用户脚本。空白页根因尚未确定。

页面定位怎样处理

针对元素抓取不准，集中配置候选选择器并依次尝试，兼容点击、焦点和输入事件。平台页面变化仍可能导致脚本失效。

如何理解统计结果

看板统计来自脚本上报的操作事件，不等于平台确认投递成功；尚需完善在途请求取消、会话一致性和发送确认。

当前状态与边界

仅展示个人技术实践。实际遇到过元素定位与平台拦截问题，尚未证明可靠解决；不宣称绕过检测或无人值守运行。

数据初始化、用户培训、问题跟踪与验收确认

典型多级审批链路（含条件分支与退回）

审批节点可配置串行 / 并行（会签、或签），支持退回指定节点、加签、转办与撤回；条件分支需显式兜底默认路由，避免出现无节点承接的「悬空流程」。

01

审批流配置

梳理审批职责、节点顺序与例外处理规则，建立可执行的流程模型。

  • 多级审批节点编排：串行逐级、并行会签 / 或签
  • 条件分支路由：按金额区间、单据类型、发起部门自动选路
  • 节点动作：同意 / 驳回 / 退回指定节点 / 加签 / 转办 / 撤回
关注点：退回后的状态与数据一致性、条件分支覆盖和默认路由，避免流程停滞。
02

表单设计

根据业务对象设计主从表、字段约束与联动规则，兼顾流程使用和数据统计。

  • 主表 + 明细表：如领用申请单下挂多项物资明细
  • 校验规则：必填、格式、唯一性、数量与库存联动校验
  • 字段级权限：同一张表单，不同角色可见 / 可编辑字段不同
关注点：明细汇总与审批信息完整性、字段权限和流程节点权限的一致性。
03

权限体系

明确组织、角色与数据范围的授权边界，落实最小权限与职责分离。

  • 组织 / 角色 / 人员三级授权，支持按岗位自动匹配审批人
  • 数据范围权限：仅本部门 / 含下级部门 / 全公司
  • 遵循最小权限原则，管理员与审批人职责分离
关注点：明确多角色权限叠加规则，以及代理、兼职人员的审批归属。
04

UAT 测试

从角色、分支和异常路径设计验收用例，以回归结果推动缺陷闭环。

  • 用例设计方法：等价类划分、边界值分析、异常流、角色走查
  • 必测场景：正常审批、驳回重提、退回修改、越权访问、并发提交
  • 缺陷登记 → 修复 → 回归验证闭环，输出测试结论再交付
关注点：覆盖发起人、审批人、管理员视角，并验证金额阈值等边界条件。
05

数据迁移

通过清洗、映射、试导与校验保证数据一致性，保留备份与回滚预案。

  • 存量数据清洗：SQL 去重、格式归一、空值与脏数据处理
  • 字段映射核对：源表与目标表逐字段比对，含编码与编号映射
  • 导入前备份、小批量试导、校验后再全量，保留回滚预案
实战：办公用品库系统导入中逐项核对管理员编号映射关系，修正错误映射后完成数据上线。
