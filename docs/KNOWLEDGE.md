# 公开知识维护

项目事实统一维护在 `frontend/content/projects.json`，包括六个项目的顺序、文案、设计取舍、材料状态、源码链接和简历要点。每份 TXT 对应一个主题，manifest.json 指定稳定 ID、资料标题与不带 # 的网站锚点，编码为 UTF-8。

维护顺序：

1. 确认资料可以公开，去除公司内部规则、账号、薪酬、个人住址等。
2. 写清“本人做了什么”“团队或平台做了什么”“哪些数据有证据”。
3. 先执行 `python scripts/sync-project-content.py` 同步六项目、简历项目、流程图和项目 TXT，再执行 `python scripts/sync-knowledge.py` 从网站与完整简历同步个人、实习八条贡献、交付闭环、44 项技能程度、校园、联系和网站指南。两个脚本都执行 `--check`，或统一运行 `python scripts/check-local.py`。生成文件不要手动重复维护。
4. 在 backend 目录执行 python -m app.cli index 后重启 API，或重新部署让新服务启动时建库。运行中的服务不会自动切换到新索引。
5. 执行 python evaluate.py，检查新资料是否被正确召回。
6. 手动提问事实问题、追问和未知问题，核对来源引用。

当前资料为 15 份公开 TXT，已建索引 41 块、1024 维（2026-10-28 基线）。资料和模型配置变更后，以新索引元数据为准。

2026-10-29 起，上述同步与问答验收先在本地完成，最终成品再发布；不因修改知识而反复推送 GitHub。具体进度见 PROJECT-STATUS.md，本地步骤见 LOCAL-DEVELOPMENT.md。知识源只包含适合对外展示的事实，不把开发操作指令、聊天历史、密钥或客户内部文档当作个人知识加入。

当前工程参数为 420 字符块、80 字符重叠。它们不是通用最优值，
短资料不必强行切成很多块。更改切分参数或 Embedding 模型会重建索引。

已移除果蔬和语音项目中无法复核的准确率与数据规模。语音项目仅保留源码与文件确证的训练样本说明，同时明确当前 HuBERT 推理未加载分类头权重、没有独立系统评测。Coze 仅描述简单搭建，不补写复杂插件或企业交付成果。流程图是链路示意，不作为运行截图或效果证明。

正式方案为 https://llywjr.love/wx/ 同域全栈部署，Nginx 托管网站并代理 systemd 后端，GitHub 仅保存源码。更换公开资料后需重建索引并重启后端，避免网站与内存知识版本不一致。
