全栈 AI 应用 · 已上线 · 同域全栈问答

项目介绍

面向面试官快速了解个人经历的需求，将作品集网站、公开知识库和独立问答服务组合为完整应用。公网入口为 http://cloud.8-152-192-126.sslip.io/wx/ ，网站与 API 在同一台 Ubuntu 云服务器运行，访客可以浏览项目、连续追问并查看参考来源。

设计背景与目标

面试官需要在浏览作品的同时了解实现细节，因此把个人网站、公开资料和独立问答 API 连接起来，让经历可以被检索、追问和核对来源。

核心功能与个人实现

  • 检索与生成

    TextLoader 加载 TXT，LangChain 重叠分块，BGE-M3 向量化与 FAISS 语义召回，再由 DeepSeek 基于资料生成回答。

  • 前后端交互

    原生 JavaScript 聊天小窗支持拖动缩放、SSE 流式回答、停止重试、来源展开、回答复制与对话导出，配套分类提问、草稿恢复和手机全屏适配。

  • 服务与交付

    FastAPI 提供问答接口，配套索引持久化、调用额度、并发限制与边界测试；Nginx 同域托管前端并反向代理，systemd 管理常驻服务。

难点、设计取舍与实践复盘

追问如何保留主题

结合最近对话补全检索问题，再进行向量召回；历史帮助理解指代，公开资料作为事实依据。

知识更新如何生效

通过脚本同步项目事实、网站与简历资料；知识内容、向量模型和切分配置共同生成索引指纹，以 FAISS 二进制与 JSON 保存索引，更新后重建并重启服务。

公开体验如何控制成本

SQLite 原子预约控制单 IP / 全局额度及并发；浏览器不持有模型密钥，模型文本通过安全 DOM 节点展示。

设计背景与目标

毕业设计以中文短语音情感分析为场景，结合声音表达与转写内容两个通道，并把模型分析接入录音、上传、可视化与历史回看流程。

核心功能与个人实现

  • 训练与服务

    基于本地 1,200 条六类样本编写冻结 HuBERT 特征的分类头训练流程；FastAPI 配合 SQLite 保存分析记录，实现模型按需加载与失败兜底。

设计背景与目标

围绕个人求职中重复筛选职位、操作页面和回复消息的需求开展实践。早期独立浏览器方案未能落地，最终使用本人已登录浏览器中的用户脚本连接模型与本地监控。

    使用最近八条聊天消息作为上下文调用 DeepSeek 生成回复；招呼语使用用户预设内容，配置通过 GM 存储保留。

  • 本地监控

    FastAPI 接收事件，SQLAlchemy / SQLite 保存记录与每日计数，SSE 向看板推送更新，并提供本地简历图片接口。

难点、设计取舍与实践复盘

方案怎样演变

最初尝试程序启动浏览器并由本人登录，但出现空白页、未完成该方案；最终改为在已登录浏览器内运行用户脚本。空白页根因尚未确定。

页面定位怎样处理

针对元素抓取不准，集中配置候选选择器并依次尝试，兼容点击、焦点和输入事件。平台页面变化仍可能导致脚本失效。

如何理解统计结果

看板统计来自脚本上报的操作事件，不等于平台确认投递成功；尚需完善在途请求取消、会话一致性和发送确认。

04业务交付与问题解决

理解客户要解决的问题，确认双方认可的方案，把需求推进到可使用、可验收、可持续维护的业务结果。

从客户需求到上线维护的交付闭环

在央国企客户驻场实施中，我围绕 OA 业务模块，与客户及协同团队推进从需求沟通到上线维护的交付过程，重点是接住需求、对齐预期、验证结果、跟进使用。

  1. 需求接收与分析，向客户复盘确认

    接收业务部门的需求，梳理使用场景、涉及人员、现有痛点和例外情况；将理解后的业务流程、处理方案与验收要点向客户复述并演示确认，对齐范围与预期，客户认可后再推进实施。

  2. 按确认方案实施，反复测试验证

    把确认后的需求转化为可用的业务功能，按真实使用场景反复自测正常流程、异常情况和角色差异；发现偏差及时调整，邀请客户试用反馈，确认实现结果与原始需求一致。

  3. 生产上线与交付演示，确认实际可用

    与客户及协同团队对齐发布安排，参与生产上线和上线后核验；按业务场景演示操作过程、说明使用要点，跟进客户验证与验收反馈，将“功能完成”推进到“业务能用”。

  4. 持续维护与问题解决，跟踪反馈到关闭

    上线后继续接收使用反馈，澄清影响并复现问题；能在实施范围内处理的及时调整，需要开发支持的提供线索并协同跟进。修复后回归验证、向客户反馈结果并确认关闭，新增诉求再进入需求分析与确认流程。

交付关注：每项需求有确认，每次上线有验证，每个问题有反馈，让客户诉求、实施结果与后续使用保持一致。
