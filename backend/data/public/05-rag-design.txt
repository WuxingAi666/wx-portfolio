【为什么用 Embedding 与 FAISS】
Embedding 把问题和文档表示为语义向量，FAISS 在这些向量中召回近邻文本。项目把查询和文档向量归一化，用平方 L2 距离换算余弦相似度。该相似度只反映语义接近程度，不是答案正确率或真实性百分比。

【上下文、持久化与追问】
重叠分块用于减少边界切断上下文。索引指纹包含知识文件、Embedding 模型与切分配置，变化后启动时构建新版本。索引使用 FAISS 二进制和 JSON 文档持久化，不反序列化任意 pickle。多轮提问先结合最近对话补全指代，再进行语义召回，避免“这个项目”失去主题。

【安全、隐私与局限】
浏览器只访问后端，不持有模型密钥。后端配置 CORS、单 IP 与全局调用额度、并发限制、输入输出上限；管理接口单独鉴权。知识库只含公开内容。当前 Embedding 和生成使用外部 API，不能称为全离线私有化推理。规模为低流量个人展示，未宣称分布式高并发能力。没有资料支撑的问题应明确说明，不编造。

【网站资料如何保持同步】
六个项目事实维护在 projects.json，经 sync-project-content.py 同步到网站、简历与项目 TXT。sync-knowledge.py 从最终网站和完整简历提取个人背景、实习八条贡献、业务交付闭环、44 项技能实践程度、校园文体经历、公开联系方式和网站使用指南。两个脚本均支持 --check；内容、模型和切分配置共同形成索引指纹。同步后重建 FAISS 索引，并重启本地后端加载新版本，不只修改 TXT 就声称已生效。

【助手交互实现】
原生 JavaScript 实现 SSE 逐字显示、停止与重试、连续追问、来源折叠和跳转；所有模型文字以 DOM 文本节点呈现。窗口可拖动、八向缩放、放大还原和最小化；手机按可视视口适配。分类提问灵感和随机问题用于帮助访客选题，不参与向量检索打分。支持复制、Markdown 对话导出、字号切换和当前标签页草稿恢复；上翻阅读时停止自动追随新消息，通过“回到最新”恢复跟随。失败或停止的回答不进入后续检索上下文。
